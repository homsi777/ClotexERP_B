# TASK 012 — Manufacturing Reference Foundation

## النتيجة

استُبدلت شاشة التصنيع التجريبية بمرحلة أولى حقيقية تعمل من المتصفح ومتصلة بـPostgreSQL عبر API. تشمل هذه المرحلة تعريف أقسام المصنع، الماكينات، حالات الماكينات وسجل انتقالاتها، الأعطال والصيانة، أسباب التوقف، ومكتبة عيوب الجودة.

لا تشمل هذه المرحلة أوامر الإنتاج أو التسدية أو التصميغ أو النسج أو فحص دفعات الإنتاج؛ ستُبنى فوق هذه التعريفات في المراحل التالية.

## قاعدة البيانات

Migration إضافية: `083_manufacturing_reference_foundation.sql`.

تضيف:

- صلاحيات تصنيع دقيقة وتمنحها لدور `admin` بصورة idempotent.
- `manufacturing_departments`.
- `manufacturing_machines` مع الملكية والقيمة والموقع والحالة ونسخة Optimistic Concurrency.
- `manufacturing_machine_status_events` كسجل انتقالات غير قابل للتعديل من الواجهة.
- `manufacturing_machine_maintenance_events` للأعطال والصيانة.
- `manufacturing_downtime_reasons`.
- `manufacturing_quality_defect_catalog`.
- فهارس للبحث حسب الشركة والحالة والقسم والنوع.
- مفاتيح مركبة تمنع ربط ماكينة بقسم يتبع شركة أخرى.
- أسباب توقف أولية محايدة مأخوذة من المتطلبات المعتمدة.

لا تعدل Migration أي سجل أعمال قديم ولا تحذف جداول أو بيانات.

## API والأمان

المسار: `/api/manufacturing/reference`.

يدعم:

- ملخص التعريفات وحالة الماكينات.
- CRUD آمن لأقسام المصنع والماكينات وأسباب التوقف وعيوب الجودة.
- تغيير حالة الماكينة داخل Transaction مع قفل السجل وسجل حدث إلزامي.
- منع انتقالات الحالة غير القانونية.
- منع Lost Update للماكينات عبر `version`.
- تسجيل أعطال وصيانة مرتبطة بالماكينة والشركة.
- تاريخ حالات وصيانة الماكينة.
- عزل `company_id` في جميع الاستعلامات.
- صلاحيات على الخادم، وليس إخفاء أزرار الواجهة فقط.
- تحقق Zod لكل مدخلات الكتابة.

## واجهة المتصفح

صفحة `/manufacturing` أصبحت تعرض بيانات فعلية، وتشمل:

- بطاقات ملخص للماكينات العاملة والمتوقفة والصيانة المفتوحة.
- تبويب الماكينات.
- تبويب أقسام المصنع.
- تبويب أسباب التوقف.
- تبويب عيوب الجودة.
- إنشاء وتعديل التعريفات حسب الصلاحيات.
- تغيير حالة الماكينة مع سبب إلزامي.
- تسجيل عطل جديد.
- عرض سجل الحالات والصيانة.
- واجهة عربية RTL وترجمة تركية مقابلة.

## محدودية التحقق

لم تُطبق Migration على قاعدة فعلية. جرت محاولة على PostgreSQL محلي فقط، لكن اتصال المشروع يستخدم منفذ Tunnel محليًا غير عامل، وخدمة PostgreSQL على المنفذ القياسي رفضت بيانات المستخدم الخاصة بالمشروع. توقفت المحاولة دون الاتصال بقاعدة بعيدة ودون تعديل أي قاعدة.

قبل الدمج أو النشر يجب تطبيق جميع Migrations على قاعدة اختبار معزولة ببيانات اعتماد صحيحة، ثم تنفيذ Smoke Test للـAPI من المتصفح. لا تُطبق على الإنتاج ضمن هذه المهمة.
