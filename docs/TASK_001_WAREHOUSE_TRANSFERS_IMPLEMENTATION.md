# مهمة 001 — إصلاح المناقلة واختيار الخامات والألوان

> تحديث: أُجريت الاختبارات الفعلية لاحقًا بإذن المالك، وطُبقت الترحيلة 040 على قاعدة الاختبار المحلية حصراً. النتائج الحالية في [تقرير الاختبار المحلي](./TASK_001_LOCAL_VERIFICATION_REPORT.md). القيود أدناه توثق مرحلة التنفيذ السابقة.

التاريخ: 2026-11-15. تغييرات محلية في الشيفرة فقط؛ لا اتصال بإنتاج أو VPS، ولا تثبيت حزم أو تشغيل خادم أو تطبيق ترحيلات.

## السبب المثبت

كان إدراج حركة المخزون في تأكيد المناقلة يحدد 14 عمودًا مقابل 15 موضع قيمة و14 معاملًا. هذا استعلام غير صالح يوقف التأكيد ويصل إلى الخطأ العام. أُزيل الاستعلام المعيب واستُبدل بخدمة معاملات موحدة. لم يُعَد إنتاج الواقعة الأصلية على قاعدة بيانات، ولا توجد سجلات تشغيل تربطها قطعًا بما شاهده المستخدم.

## الاختيار والمراجعة

- أربعة أوضاع: رولة منفردة، خامات متعددة، خامة بالكامل، حسب اللون.
- الألوان مشتقة من الرولات المتاحة ذات الطول الموجب للخامة الموجودة في مستودع وموقع المصدر المحددين.
- اختيار لون يضيف رولات ذلك اللون، مع إبقاء إمكانية استبعاد أي رولة، وإضافة خامات وألوان أخرى.
- جميع الطرق تتشارك قائمة رولات واحدة بلا تكرار ومستند مناقلة واحد.
- تحميل كل الصفحات دون حد 30 صفحة. التحميل الناقص أو الذي لا يحقق تقدمًا يفشل برسالة واضحة بدل تحديد مجموعة ناقصة بصمت.
- تغيير المصدر أو موقعه يمسح الاختيار فورًا؛ تُهمل استجابات التحميل القديمة.
- مراجعة مجمعة حسب الخامة واللون، تعرض الكود والباركود والأمتار والأوزان والمستودع والموقع والإجماليات.
- يُستخدم الوزن الفعلي عند توفره، وإلا المحسوب مع تمييزه؛ الأوزان المجهولة لا تعرض كأنها صفر معلوم.
- فتح المسودة للمراجعة يستخدم بيانات الرولات الحالية من استجابة واحدة، دون طلب منفصل لكل رولة.

## سلامة التنفيذ

- حفظ المسودة والتأكيد والإلغاء والتعديل تستخدم معاملاتها الخاصة؛ جميع آثار التأكيد ذرية داخل معاملة واحدة.
- قفل المستند والمستودعات والمواقع والرولات، مع ترتيب ثابت لقفل الرولات.
- التحقق من الشركة ونشاط المستودعات والمواقع، واختلاف المستودعين، وتبعية الرولات للمصدر والموقع، وحالتها AVAILABLE وطولها الموجب، وكمية رولة كاملة، ومنع التكرار.
- إعادة التحقق عند التأكيد، وفحص نسخة المستند التي راجعها المستخدم قبل التنفيذ.
- التعديل والإلغاء لا يستطيعان تجاوز قفل التأكيد؛ التأكيد المكرر يعيد النتيجة دون حركات أخرى.
- معرف طلب وبصمة محتوى وقفل استشاري وقيد تفرد تمنع تكرار إنشاء المسودة من نفس الطلب. إعادة استخدام المعرف مع محتوى مختلف مرفوضة.
- النقل يحافظ على معرف الرولة وحالتها المتاحة والطول والوزن والتكلفة. تسجل حركتا خروج ودخول دون فروق كمية عامة أو قيد محاسبي.
- مسار نقل الرولة المنفردة يستخدم التحقق والقفل المشتركين ويحافظ على تغيير الموقع داخل المستودع.
- كتابة المناقلات ونقل الرولة تتطلب inventory.manage، مع استمرار تجاوز المدير المعتاد للصلاحيات.
- أخطاء عربية وتسجيل تقني محدود بمعرف الطلب والعملية ورمز الخطأ، دون جسم الطلب أو الأسرار.
- حد الطلب 16 MiB؛ الطلب الأكبر يُرفض صراحةً دون تقسيم المناقلة أو ترحيل جزء منها.

## الترحيلة

أُضيفت `server/src/db/migrations/040_inventory_transfer_idempotency.sql` لإضافة معرف الطلب وبصمته وقيد التفرد. لم تُطبّق على أي قاعدة بيانات. يلزم تطبيقها على قاعدة تطوير محلية معزولة قبل استخدام إنشاء المناقلات في هذه النسخة؛ المخطط القديم سيعيد رسالة عدم اكتمال الإعداد.

لا تُعدَّل بيانات الرولات القديمة التي تحمل TRANSFERRED تلقائيًا. إصلاحها يحتاج تدقيقًا منفصلًا.

## التحقق المنفذ

نجح 17 اختبارًا آليًا: أهلية الرولات والمواقع والحالات، الدمج ومنع التكرار، إلغاء الاختيار الفردي، تحميل أكثر من 30 صفحة، إهمال استجابة قديمة، الإجماليات والأوزان المجهولة، التحقق الخلفي، نقل جميع الرولات مع الحفاظ على الكميات والتكلفة، إعادة التأكيد، إعادة الطلب، بصمة الطلب، التراجع بعد فشل مُحاكى في الرولة الثانية، ورفض نسخة المستند القديمة والإلغاء غير المسموح. يشمل ذلك اختبار فصل اللون المشترك بين خامتين واختبار تجميع المراجعة حسب الخامة واللون مع الحفاظ على الإجماليات.

اختبارات الخدمة تستخدم بديل SQL حتميًا؛ تثبت مسار الخدمة واستدعاء COMMIT/ROLLBACK وتطابق عدد المعاملات، ولا تثبت تنفيذ SQL أو أقفال PostgreSQL الحقيقية.

نجح فحص الصياغة لـ11 ملف TS/TSX، والفحص النوعي الصارم لملف منطق الاختيار المستقل. استُخدم محرك Node ومترجم TypeScript الموجودان مع VS Code دون تثبيت أو تشغيل واجهة VS Code أو خدمة.

## غير المختبر

- تكامل PostgreSQL الفعلي والتراجع الحقيقي والتزامن والأقفال: أُضيفت مجموعة اختبارات اختيارية، وتُخطيت أثناء هذا التنفيذ دون أي اتصال.
- تشغيل React في المتصفح أو Electron واختبارات العرض والتفاعل.
- فحص الأنواع الكامل والبناء واختبارات المشروع السابقة؛ node_modules غير موجود ولا توجد أدوات Node/npm مستقلة في PATH.
- الأداء مع مخزون ضخم، والتوافق مع بيانات الأعمال القديمة والتقارير على قاعدة فعلية.

## إعادة الاختبار لاحقًا

بعد توفر اعتماديات المشروع محليًا، الأمر `npm run test:transfers` يشغل الاختبارات، مع تخطي تكامل PostgreSQL افتراضيًا.

لتكامل PostgreSQL يلزم إذن وتشغيل قاعدة اختبار محلية مستقلة، وتعيين `CLOTEX_TRANSFER_LOCAL_TESTS=1` و`CLOTEX_TRANSFER_TEST_DATABASE_URL` إلى قاعدة باسم يبدأ `clotex_transfer_test_` على `127.0.0.1:5432` بلا خيارات URL، والتأكد أنها PostgreSQL محلية فعلًا وليست نفقًا. الاختبار ينشئ مخططًا عشوائيًا داخل قاعدة الاختبار ثم يحذفه، ولا يحمل ملفات .env أو إعدادات التطبيق. لا تُستخدم بيانات الإنتاج.

تغطي المجموعة الاختيارية النقل المفرد والمتعدد والكامل، وفشل SQL في منتصف التأكيد، والمطابقة قبل وبعد، وتحويلين متعارضين بالتزامن، وإنشاءين بالمفتاح نفسه، وتأكيدين متزامنين للمستند نفسه.
