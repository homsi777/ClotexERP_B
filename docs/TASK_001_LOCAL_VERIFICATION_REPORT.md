# TASK 001 — نتائج الاختبار المحلي الفعلي

التاريخ: 2026-11-15. هذا التقرير يحل محل قيود الاختبار الواردة في تقرير التنفيذ السابق.

## العزل والتجهيز

- Node.js 22.14.0 محمولة داخل `.local-test-tools`، مع التحقق من SHA-256 مقابل الملف الرسمي.
- PostgreSQL 16.4 محمولة، بلا خدمة Windows دائمة أو صلاحيات مسؤول. هذه نسخة اختبار محلية وليست توصية لإصدار إنتاج.
- بيانات PostgreSQL داخل `.local-test-tools/pgdata`، والاستماع على `127.0.0.1:5432` فقط.
- قاعدة الاختبار الوحيدة: `clotex_transfer_test_task001`. تحقق المشغل من عنوان الخادم والمنفذ واسم القاعدة ومسار بيانات النسخة المعزولة قبل تطبيق الترحيلات.
- نجحت الترحيلات 001–040 على القاعدة الفارغة؛ تم تسجيل 40 ملفًا في `schema_migrations`.
- بيانات وهمية وحسابات اختبار فقط، دون قراءة ملفات .env أو استخدام أسرار الشركة.
- API اختبار على `127.0.0.1:14030` وVite على `127.0.0.1:13030`. إعداد Vite منفصل لا يحمّل إعدادات البيئة أو إعداد Vite الإنتاجي.
- متصفح الاختبار يحظر الطلبات خارج عنواني الاختبار المحليين.
- أُضيفت تعريفات React وReact DOM للتطوير، وتحدّث ملف القفل. تم تعطيل lifecycle scripts أثناء التثبيت؛ لم تُشغّل أدوات Electron أو الأنفاق.
- احتاج npm إلى الشهادات العامة الموثوقة في Windows؛ لم يُعطّل التحقق من TLS ولم تُصدّر مفاتيح خاصة.
- مجلدا الأدوات والنتائج مستبعدان من Git، ولا توجد عملية رفع أو نشر.

## ما اختُبر فعليًا

- إنشاء وتأكيد النقل المفرد والمتعدد والخامة الكاملة والاختيار حسب اللون.
- واجهة الاختيار: 1 رولة مفردة، و4 رولات لخامات متعددة، و3 رولات لخامة كاملة، و3 رولات في سيناريو اللون الذي يجمع لونين واستبعادًا فرديًا وخامة ثانية.
- احترام موقع المصدر، وفصل ألوان الخامات، وحفظ الاختيارات في مستند واحد بلا تكرار.
- الحفاظ على الباركود والأمتار والأوزان والتكلفة والعملة والحالة المتاحة بعد النقل.
- حركتا خروج ودخول لكل رولة دون تغير إجمالي الكمية أو قيد محاسبي؛ جدول اليومية بقي فارغًا في شركة الاختبار.
- حقن فشل PostgreSQL عند حركة الرولة الثانية: تراجعت كل تحديثات الرولات والحركات وبقي المستند مسودة.
- تحويلان متعارضان للرولات نفسها: نجاح واحد ورفض الآخر دون نقل جزئي.
- طلبان متزامنان بالمفتاح نفسه: مستند واحد فقط. تأكيدان للمستند نفسه: تنفيذ واحد فقط.
- رفض الكمية غير الكاملة والمستودع غير الموجود أو غير النشط والموقع غير الصحيح والرولة التي تغير مصدرها.
- رفض RESERVED وSOLD وDAMAGED وINACTIVE وTRANSFERRED.
- رفض تغيير محتوى الطلب مع إعادة استخدام مفتاحه، ورفض تأكيد نسخة مراجعة قديمة.
- الإلغاء والتأكيد المتزامنان: نتيجة متسقة مع موضع الرولة النهائي.
- مستخدم viewer لا يستطيع إنشاء مناقلة.

## إصلاحات ظهرت أثناء الاختبار

- منع استنتاج TypeScript لنوع الكمية على أنه القيمة الحرفية 1 داخل Zod، مع الإبقاء على التحقق الفعلي بأن الكمية تساوي 1؛ أصبح النوع مناسبًا لقراءة الكميات من قاعدة البيانات.
- تحديد نوع FastifyError في معالج أخطاء المناقلة؛ أصبح فحص الخادم الكامل ناجحًا.
- إعداد محرك اختبار Vite بمهلة تحميل مناسبة وذاكرة اعتماديات داخل node_modules؛ نجح الاختبار بعد مهلة التحميل الأولى.

لم يُختبر تغليف Electron أو الطابعات أو الأداء تحت حجم إنتاجي أو تدقيق أمني شامل للاعتماديات. لم يحدث أي اتصال بالإنتاج أو تعديل إعداداته أو نشر أو رفع إلى GitHub.

تُوقف خدمات الاختبار بعد اكتمال التحقق، وتُترك القاعدة والبيانات الوهمية والأدوات محليًا لإعادة الاختبار لاحقًا.
