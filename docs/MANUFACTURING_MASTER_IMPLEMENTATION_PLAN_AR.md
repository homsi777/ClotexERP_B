# الخطة الهندسية الرئيسية لنظام تصنيع CLOTEX

## 1. حالة الوثيقة ونطاقها

- الحالة: تصميم هندسي معتمد مبدئيًا، يسبق التفصيل والتنفيذ البرمجي.
- المنصة المستهدفة حاليًا: تطبيق ويب يعمل من المتصفح فقط.
- خارج النطاق الحالي: Electron، تطبيق Windows مستقل، تطبيق جوال أصلي، وأي نشر أو تعديل إنتاجي.
- المصدر التجاري الأولي: ملف `تاسكات تصنيع وغيرها.md`.
- المصدر التقني: البنية الحالية الفعلية لمشروع CLOTEX وجداول PostgreSQL وخدمات API والواجهات الموجودة.
- لا تعد هذه الوثيقة إذنًا تلقائيًا لتنفيذ جميع المراحل دفعة واحدة. تُنفذ كل مرحلة كتاسك مستقل بعد مراجعة تفاصيلها واعتمادها.

## 2. المبادئ الحاكمة

1. قاعدة PostgreSQL هي مصدر الحقيقة الوحيد للعمليات الصناعية.
2. لا يُعتد بأي بيانات تجريبية أو حالة محفوظة في React وحده.
3. تُطوّر وحدات الأوردرات والمخزون والخيط والفواتير والمصنعية الخارجية وHR الموجودة، ولا تُنشأ نسخ موازية منها.
4. لا تتغير الكميات المؤكدة بتعديل مباشر؛ كل تغيير مخزني ينتج عن حركة قابلة للتدقيق.
5. كل عملية حساسة تُنفذ داخل Transaction واحدة مع أقفال مناسبة ومنع التكرار Idempotency.
6. كل سجل تشغيلي يحمل `company_id` ويخضع لعزل الشركة على مستوى الاستعلامات والقيود.
7. صلاحيات الخادم إلزامية؛ إخفاء الزر في الواجهة ليس حماية.
8. المواصفات والوصفات ومسارات الإنتاج تُحفظ بإصدارات. المستند التاريخي يحتفظ بالنسخة التي نُفذ بها.
9. لا تُعتمد معادلة استهلاك أو تكلفة غير معتمدة من الإدارة.
10. الحالة، الموقع، الملكية، الحجز، والجودة مفاهيم منفصلة ولا تُضغط في حقل واحد.
11. واجهة التصنيع الرئيسية لوحة متابعة وتنقل؛ كل مرحلة تشغيلية لها شاشة ومسؤوليات مستقلة.
12. الواجهات عربية RTL أولًا، مع المحافظة على نظام تصميم CLOTEX الحالي ودعم التركية بحسب نمط المشروع.

## 3. الوضع الفعلي الحالي

### موجود ويُعاد استخدامه

- العملاء والأوردرات وبنود الأوردر وربطها بفواتير المبيعات.
- فواتير المبيعات والتسليم الجزئي وحساب المنفذ والمتبقي على بنود الأوردر.
- مستودعات ومواقع تخزين.
- رولات القماش وباركوداتها وحركات المخزون.
- الكارتيلات والأصناف والألوان وبعض المواصفات الأساسية.
- دفعات خيط أولية `yarn_lots` وحركات خيط أولية.
- المصنعية الخارجية، الإرسال، الاستلام على دفعات، التسعير، العيوب وتسوية النقص.
- الموظفون والحضور والمراجعة الشهرية والرواتب.
- نظام مستخدمين وأدوار وصلاحيات وسجل تدقيق أساسي.
- مركز تقارير قابل للتوسعة.

### غير موجود كنظام حقيقي

- أمر إنتاج مركزي.
- تخصيص الإنتاج لأوردرات العملاء أو المخزون.
- بطاقة مواصفات تصنيع كاملة بإصدارات.
- مسار إنتاج معتمد لكل صنف.
- أوامر التسدية والمطاوي.
- تشغيلات التصميغ.
- تشغيل الأنوال وإنتاج الورديات.
- قاعدة أصول الماكينات وصيانتها الصناعية.
- فحص جودة صناعي موحد للخام والمجهز.
- سجل تكلفة صناعية موحد.
- لوحة تصنيع حقيقية؛ الصفحة الحالية Mock وتُستبدل تدريجيًا.

## 4. القرارات التجارية المعتمدة مبدئيًا

### 4.1 إغلاق أوردر العميل

- لا يُغلق الأوردر تلقائيًا بمجرد اكتمال التسليم.
- عندما تصبح كل الكميات منفذة ومسلّمة ينتقل إلى `FULFILLED_PENDING_CLOSE`.
- يراجعه مسؤول مخول ثم ينفذ الإغلاق اليدوي إلى `CLOSED`.
- الإغلاق لا يحذف حجزًا أو حركة أو فاتورة، ولا يعالج فرقًا غير مسوّى بصمت.

### 4.2 اعتماد العينة

- العينة اختيارية افتراضيًا ولا تمنع الإنتاج.
- يملك الأوردر حقل سياسة عينة مستقل:
  - `NOT_REQUIRED`
  - `TRACK_ONLY`
  - `APPROVAL_REQUIRED_BEFORE_PRODUCTION`
- إذا كانت السياسة تتطلب الاعتماد، يمنع الخادم إصدار أمر إنتاج قبل الاعتماد.

### 4.3 الإنتاج لأكثر من أوردر

- يسمح لأمر إنتاج أو تسدية مشترك بخدمة أكثر من أوردر عند تطابق المواصفات المعتمدة.
- تُحفظ حصة كل سطر أوردر في سجل تخصيص مستقل.
- لا توزع الكميات أو التكلفة بالتخمين؛ يجب أن يكون مجموع التخصيصات مساويًا لكمية الأمر أو يظهر فرق صريح.

### 4.4 هوية المطواية بعد التصميغ

- ناتج التصميغ جسم تشغيلي جديد برقم وباركود جديدين.
- يبقى الارتباط بالمطواية الأصلية إلزاميًا ضمن شجرة النسب Genealogy.
- لا تُحذف أو تُستبدل هوية المطواية الأصلية.

### 4.5 الجودة

- الفحص الموحد يدعم أنواعًا متعددة، ولا يفترض قائمة فحص واحدة للجميع.
- حدود الفروقات التي تتطلب اعتمادًا تُحفظ في إعدادات قابلة للإدارة حسب نوع الفحص أو الصنف.
- الكمية المعلقة أو المرفوضة لا تصبح متاحة للحجز أو البيع.

### 4.6 التكلفة

- يبدأ النظام بتجميع الكميات والتكاليف الفعلية المتاحة.
- أي عنصر تكلفة بلا سياسة معتمدة يظهر `UNRATED` ولا يُستبدل بقيمة تقديرية.
- المصنعية الداخلية توزيع تكلفة على أمر الإنتاج، وليست حركة نقدية أو ذمة مورد.
- الرواتب لا تُحتسب مرتين: إن دخلت أجور العاملين ضمن تكلفة الإنتاج، يكون المصدر من تكلفة رواتب معتمدة أو معدل إداري واضح.
- قيمة الماكينة تسجل كبيان أصل فقط. لا يحسب الإهلاك قبل اعتماد سياسة الأصول.

## 5. نموذج الدومين المركزي

الأسماء أدناه مفاهيم منطقية؛ تُثبت أسماء الجداول النهائية أثناء تصميم كل Migration.

### 5.1 المواصفات والمسارات

- `manufacturing_spec_cards`: هوية بطاقة المواصفة وحالتها.
- `manufacturing_spec_versions`: نسخة غير قابلة للتغيير بعد الاعتماد.
- `manufacturing_spec_sections`: السداء، اللحمة، التركيب، اللقي، وأمر الشغل.
- `manufacturing_routes`: مسار الإنتاج المعتمد للصنف.
- `manufacturing_route_steps`: ترتيب المراحل وما إذا كانت اختيارية أو إلزامية.
- `consumption_formula_versions`: المعادلات المعتمدة وإصدارها ومدخلاتها ووحداتها.

### 5.2 أمر الإنتاج والتخصيص

- `production_orders`: رأس أمر الإنتاج، مصدره أوردر أو مخزون، والمواصفة والمسار المجمدان.
- `production_order_allocations`: حصص أسطر الأوردرات أو حصة المخزون العام.
- `production_order_steps`: نسخة مراحل المسار وحالة كل مرحلة.
- `production_order_events`: أحداث الحالة والتدقيق والتعليقات المنظمة.

### 5.3 المواد والعهدة

- `material_requirements`: الاحتياج المحسوب ومصدر المعادلة وجودة الحساب.
- `material_issues`: سند صرف مؤكد من المخزن إلى أمر/مرحلة.
- `material_issue_lines`: اللوط والكمية والوحدة والمالك.
- `material_returns`: المرتجع الذي لا يدخل الرصيد قبل تأكيد المخزن.
- `material_consumptions`: المستهلك الفعلي.
- `material_waste`: الهالك وسببه واعتماده.
- لا يُستنتج الاستهلاك من الصرف وحده.

### 5.4 الأجسام التشغيلية وشجرة النسب

- `warp_orders`: أوامر التسدية.
- `warp_beams`: المطاوي الناتجة من التسدية.
- `sizing_runs`: تشغيلات التصميغ، واحدة لكل مطواية.
- `sized_beams`: المطاوي الناتجة من التصميغ.
- `weaving_runs`: تشغيل المطواية على نول.
- `production_batches`: إنتاج ماكينة/وردية/أوردر.
- `production_genealogy`: علاقة المصدر والناتج بين الخيط والمطاوي والدفعات والرولات.
- `production_object_allocations`: توزيع الجسم التشغيلي على أوردرات متعددة عند الحاجة.

### 5.5 الماكينات والتشغيل

- `machines`: بطاقة الماكينة، نوعها، موقعها، ملكيتها وحالتها.
- `machine_status_events`: تغيرات الحالة.
- `machine_maintenance_events`: الأعطال والصيانة والإصلاح.
- `shift_production_logs`: قراءات العداد والإنتاج لكل وردية.
- `shift_workers`: مشاركة الموظفين الفعلية في التشغيل.
- `downtime_events`: التوقف والسبب والمدة.
- حضور HR مرجع مستقل ولا ينشئ مشاركة إنتاجية تلقائيًا.

### 5.6 الجودة

- `quality_inspections`: سجل موحد مع `inspection_type` ومرجع المصدر.
- `quality_quantity_results`: مقبول، معالجة، مرفوض، هالك، أو معلق.
- `quality_defect_catalog`: مكتبة العيوب حسب نوع الفحص.
- `quality_defects`: العيب والدرجة والموقع والصورة والملاحظة.
- `quality_dispositions`: قبول، إعادة عمل، فرز، شطب أو مسار آخر.
- `quality_approvals`: الاعتماد وحدود الصلاحية.

### 5.7 التكلفة

- `production_cost_entries`: سجل تكلفة غير قابل للمحو، مرتبط بالمصدر.
- أنواع المصدر: مادة، مصنعية داخلية، خدمة خارجية، هالك، رواتب معتمدة، أو تسوية.
- `production_cost_allocations`: توزيع التكلفة بين أوردرات/كميات مشتركة.
- `production_cost_snapshots`: لقطة تكلفة بعد إغلاق مرحلة أو أمر.
- لا ينشأ قيد GL تلقائي قبل اعتماد سياسة الربط المحاسبي لكل نوع تكلفة.

## 6. نماذج الحالات

### 6.1 أوردر العميل

`DRAFT → CONFIRMED → SUPPLY_REVIEW → PARTIALLY_READY/READY → PARTIALLY_DELIVERED → FULFILLED_PENDING_CLOSE → CLOSED`

حالات جانبية مضبوطة:

- `ON_HOLD`
- `CANCEL_PENDING_APPROVAL`
- `CANCELLED`

الحالة العامة مشتقة من البنود والأحداث، مع تخزينها لتحسين البحث بعد ضمان تحديثها داخل المعاملة نفسها.

### 6.2 أمر الإنتاج

`DRAFT → APPROVED → MATERIALS_PENDING → IN_PROGRESS → QUALITY_PENDING → COMPLETED → CLOSED`

حالات جانبية:

- `ON_HOLD`
- `CANCEL_PENDING_APPROVAL`
- `CANCELLED`

لا يجوز إلغاء أمر بدأ صرف مواد له بحذف البيانات؛ يعالج المتبقي والمرتجع والهالك ثم يغلق بسجل واضح.

### 6.3 مرحلة إنتاج

`PENDING → READY_TO_START → IN_PROGRESS → PENDING_INSPECTION → COMPLETED`

حالات جانبية:

- `BLOCKED`
- `REWORK`
- `REJECTED`
- `SKIPPED` للمراحل الاختيارية فقط وبصلاحية وسبب.

## 7. فصل الموقع والحالة والجودة

كل جسم مخزني أو تشغيلي يملك مفاهيم مستقلة:

- `location_type/location_id`: مستودع، موقع، قسم، ماكينة، جهة خارجية أو عهدة أمر.
- `availability_status`: متاح، محجوز، مستهلك، مباع أو غير فعال.
- `quality_status`: بانتظار الفحص، مقبول، معالجة، مرفوض أو هالك.
- `ownership_type/owner_id`: ملك الشركة أو أمانة عميل/طرف.
- `reservation_reference`: المستند المستفيد من الحجز.

الكمية القابلة للبيع أو الصرف تُحسب من اجتماع الشروط، وليس من قيمة `status` واحدة.

## 8. محرك الحجز الموحد

تُرقّى آلية `RESERVE/RELEASE_RESERVATION` الحالية إلى محرك عام:

- سجل حجز مستقل يحمل الرول أو اللوط، سطر الأوردر، الكمية، الحالة، المنشئ والتواريخ.
- يدعم حجز الرول كاملًا أو كمية جزئية فقط عندما يسمح نموذج المخزون بذلك.
- الاختيار الآلي FEFO/FIFO لا يُفترض؛ القاعدة الأولية «أقدم رصيد مؤهل» مع قدرة المستخدم على التعديل.
- اختيار الرصيد وقفل السجلات وتسجيل الحجز يحدث داخل Transaction واحدة.
- تمنع قاعدة البيانات تجاوز الرصيد أو حجز جسم غير مؤهل.
- مسودة الفاتورة تستخدم المحرك نفسه، ولا تبقى لها آلية حجز خاصة مستقلة.
- تحرير الحجز ينتج حدثًا وحركة واضحة ولا يمحو السجل.

## 9. تطوير مخزون الخيط الحالي

يُطوّر `yarn_lots` ولا يُنشأ بديل له:

- مكتبات مادة الألياف، نوع الغزل، النمرة، نظام النمرة، الخليط واللون.
- فصل تعريف صنف الخيط عن دفعة الاستلام واللوط.
- ملكية الشركة أو العميل.
- طرد رئيسي وطرود فرعية بأوزان فعلية عند الحاجة.
- صافي الوزن والقائم والفوارغ مع حفظ المدخلات.
- منع تعديل الوزن مباشرة بعد التأكيد.
- كل استلام وصرف وإرجاع وتحويل وهالك وتسوية وحركة خارجية تسجل في Ledger.
- نقل الصرف إلى عهدة أمر الإنتاج، ثم تسجيل المستهلك والمرتجع والهالك مستقلًا.
- دعم جهة خارجية ولوط ناتج مرتبط باللوط الأصلي.
- استيراد افتتاحي بمعاينة ومفتاح Import يمنع التكرار.

## 10. تكامل المصنعية الخارجية

تُبنى الإضافة فوق `external_jobs` الحالية:

- ربط اختياري على مستوى كل بند بـ`production_order_allocation` أو `customer_order_line`.
- البند بلا ربط يعامل كمخزون عام.
- الحفاظ على الاستلام على دفعات والخدمات والتسويات وحواجز الجودة الحالية.
- توجيه الرول الراجع إلى الجودة الموحدة بدل إنشاء فحص مكرر.
- ربط نتيجة الجودة بالرول الناتج والرول الأصلي والمهمة والبند والأوردر إن وجد.
- عدم تحديث أي أوردر من مهمة غير مرتبطة به.

## 12. مراحل التنفيذ المعتمدة

### PHASE-00: اكتشاف وتثبيت قرارات المصنع

المخرجات:

- قاموس المصطلحات والوحدات.
- مخطط العملية الواقعية من الأوردر حتى التسليم.
- عينات النماذج وملفات Excel الأصلية.
- معادلات الاستهلاك المعتمدة أو توثيق أنها غير متاحة.
- قائمة الماكينات والأقسام والورديات.
- قائمة العيوب وحدود الاعتماد.
- سياسة التكلفة والصلاحيات.

لا Migration ولا واجهات تشغيلية في هذه المرحلة.

### PHASE-01: مكتبة المواصفات والإصدارات

- استيراد Excel بمعاينة، مع حفظ الملف الأصلي وحقول منظمة.
- إصدار واعتماد وإلغاء تفعيل.
- أمر شغل وكارت سداء من نسخة معتمدة.
- منع تغيير المستند التاريخي بتعديل البطاقة الأم.
- اختبار الاستيراد المتكرر والنسخ والصلاحيات.

### PHASE-02: الماكينات والجودة والبيانات المرجعية

- الماكينات والمواقع والملكية والحالة والصيانة.
- مكتبات التوقف والعيوب وقرارات الجودة.
- إعدادات حدود الفروقات والاعتماد.

### PHASE-03: نواة أمر الإنتاج والتخصيص

- أمر إنتاج للمخزون أو للأوردر.
- نسخة المواصفة والمسار.
- تخصيص أوردرات متعددة.
- أحداث الحالة وسجل التدقيق ومنع الانتقالات غير القانونية.
- لا تنفيذ مراحل صناعية تفصيلية بعد.

### PHASE-04: مخزون الخيط الكامل

- تطوير الجداول الحالية والمكتبات والطرود والملكية.
- Ledger الحركات والعهدة والصرف والمرتجع والهالك.
- الاستيراد الافتتاحي والتقارير والصلاحيات.

### PHASE-05: الأوردر والحجز والربط بالإنتاج

- الفرع والمندوب ومسؤول المتابعة وسياسة العينة.
- سطور مرتبطة بأصناف وألوان فعلية بدل النصوص فقط.
- محرك الحجز العام والحجز الجزئي.
- تحليل الجاهز والخام والخارجي والمعلق.
- إنشاء اقتراح إنتاج بعد موافقة المستخدم.
- الفواتير الجزئية والكمية المتبقية والإغلاق اليدوي.

### PHASE-06: التسدية

- أمر التسدية وصرف الخيط إلى العهدة.
- تشغيل جزئي ودفعات صرف.
- مطاوي وباركودات وشجرة نسب.
- الفحص والمرتجع والهالك واعتماد الفرق.
- التوجيه للتصميغ أو النسج.

### PHASE-07: التصميغ

- وصفات بإصدارات ومواد استهلاكية.
- تشغيلة واحدة لكل مطواية.
- تشغيل وتوقفات وقياسات.
- ناتج بباركود جديد ونسب محفوظ.
- فحص ومنع الانتقال غير المعتمد.

### PHASE-08: النسج وإنتاج الورديات

- تركيب المطواية على الماكينة.
- قراءات عداد وتوقفات وعمال ووردية.
- دفعة إنتاج بإجمالي الوردية.
- منع تضارب تشغيل الماكينة أو المطواية في الوقت نفسه.

### PHASE-09: الجودة وإدخال الخام

- فحص خام ومجهز عبر المحرك نفسه.
- تقسيم الكميات وعيوب واعتمادات وقرارات.
- إدخال الرولات عبر شاشة المخزون الحالية.
- مطابقة مجموع أطوال الرولات مع نتيجة الجودة.
- منع توفر أي كمية قبل اعتمادها وإدخالها الفعلي.

### PHASE-10: المصنعية الخارجية والتتبع

- ربط بنود المصنعية بالتخصيصات والأوردرات.
- تحويل فحص الراجع إلى الجودة الموحدة.
- المحافظة على دورة المصنعية الحالية والبيانات التاريخية.

### PHASE-11: التنبيهات والتقارير

- لوحة المصنع والأوردرات المتأخرة.
- إنتاج الماكينات والورديات والتوقفات.
- استهلاك الخيط والمرتجع والهالك.
- الجودة وإعادة العمل.
- WIP ومواقع المواد والمطاوي والرولات.
- إشعارات قابلة لإعادة المحاولة ومنع الإرسال المكرر.

### PHASE-12: التكلفة والتكامل المالي

- Ledger تكلفة الإنتاج ومصادره.
- سياسات المصنعية الداخلية والتوزيع.
- الخدمات الخارجية والهالك والرواتب المعتمدة.
- تكلفة الوحدة وجودة التكلفة: كاملة، جزئية أو غير معتمدة.
- الربط بـGL مرحلة مستقلة بعد اعتماد المحاسب.

## 13. متطلبات مشتركة لكل مرحلة

- Migration إضافية وآمنة ولا تعتمد على حذف بيانات قديمة.
- Backfill واضح للبيانات القديمة أو تركها `UNKNOWN` بدل اختراع قيم.
- Tenant isolation في كل قراءة وكتابة.
- تحقق Zod أو النمط المعتمد في المشروع على حدود API.
- معاملات وقفل سجلات لمسارات المخزون والحجز والحالة.
- مفاتيح Idempotency للعمليات التي يمكن إعادة إرسالها من المتصفح.
- Optimistic concurrency أو رقم نسخة لمنع الكتابة فوق تعديل مستخدم آخر.
- Audit log للقيم قبل وبعد في التعديلات الحساسة.
- Pagination وفهارس للبحث حسب الرقم والحالة والتاريخ والأوردر والماكينة والموظف.
- رسائل خطأ عربية واضحة، ومفاتيح ترجمة تركية متطابقة.
- لا اعتماد على LocalStorage لحفظ مستند تجاري أو حالة تشغيل.
- لا اتصال أو تعديل لقاعدة الإنتاج أثناء التطوير دون تفويض مستقل.

## 14. استراتيجية التحقق

لكل مرحلة يجب وجود:

1. اختبارات انتقالات الحالة المسموحة والمرفوضة.
2. اختبارات عزل الشركة.
3. اختبارات الصلاحيات لكل عملية حساسة.
4. اختبارات التزامن ومنع الصرف أو الحجز المزدوج.
5. اختبارات Idempotency لإعادة الطلب.
6. اختبار Migration على قاعدة فارغة وعلى نسخة بيانات تطويرية ممثلة.
7. اختبارات التكامل من API إلى PostgreSQL.
8. سيناريو يدوي من المتصفح لدور مخزن ودور مشرف ودور جودة ودور مسؤول.
9. مطابقة كميات قبل/بعد وعدم وجود رصيد سالب أو كمية مفقودة.
10. تقرير نتائج فعلية، مع الفصل بين ما اختُبر وما لم يُختبر.

## 15. بوابات الاعتماد

لا تبدأ المرحلة التالية قبل تحقق ما يلي:

- اعتماد نموذج البيانات والحالات للمرحلة.
- توفر بيانات المصنع اللازمة وعدم الاعتماد على افتراضات.
- نجاح Migration والاختبارات المرتبطة.
- مراجعة الأثر على الوحدات الموجودة.
- مراجعة الصلاحيات والعزل والأداء.
- تجربة المستخدم للمسار من المتصفح.
- موافقة نبيل على نتيجة المرحلة وسلوكها التشغيلي.

## 16. عناصر لازمة قبل PHASE-01

- ملف بطاقة المواصفات الأصلي المشار إليه باسم `2(2).xlsx`.
- ملف `كارت السداء.xlsx` الأصلي.
- مثال معتمد لأمر الشغل المطبوع.
- شرح الحقول والرسومات والألوان التي تحمل معنى تشغيليًا في Excel.
- قائمة أولية بالماكينات وأقسامها.
- قائمة أولية بأسباب التوقف والعيوب.
- تأكيد الوحدات المستخدمة فعليًا لكل مرحلة.

الروابط `sandbox:/...` الموجودة في ملف المهام ليست ملفات محلية قابلة للاستخدام داخل المستودع؛ يجب توفير النسخ المرجعية داخل نطاق المشروع عند بدء تحليل الاستيراد.

## 17. تعريف النجاح النهائي

يُعد نظام التصنيع مكتملًا عندما يمكن تتبع أوردر أو إنتاج مخزون من المواصفة المعتمدة، مرورًا بالخيط والصرف والتسدية والتصميغ والنسج والجودة والتجهيز الخارجي والمخزون، حتى الفاتورة والتسليم، مع:

- كميات متوازنة وقابلة للمطابقة.
- شجرة نسب لكل مادة وناتج.
- صلاحيات وتدقيق كاملين.
- عدم وجود حجز أو صرف مزدوج.
- تقارير تشغيل وتكلفة مبنية على بيانات فعلية.
- عدم ازدواج الحركات المخزنية أو المالية.
- بقاء البيانات التاريخية صحيحة بعد تعديل المواصفات والإعدادات.
- عمل جميع المسارات المعتمدة من المتصفح دون الاعتماد على Electron.
