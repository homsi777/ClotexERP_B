# تقرير بنية مشروع CLOTEX ومسؤوليات أقسامه

**تاريخ إعداد التقرير:** 20 نوفمبر 2026  
**المشروع:** CLOTEX — Clothes Textile  
**الغرض:** وصف أقسام المستودع البرمجي والمهام التي تنفذها كل طبقة ووحدة، اعتماداً على الشيفرة والإعدادات الموجودة في المشروع.

## 1. الملخص التنفيذي

المشروع نظام ERP لإدارة أعمال الأقمشة والمستودعات. وهو ليس واجهة منفردة؛ بل يتكون من واجهة React/TypeScript، وخادم API مبني على Fastify/TypeScript، وقاعدة PostgreSQL تُدار عبر ملفات ترحيل SQL، إضافة إلى تطبيق سطح مكتب Windows مبني بـ Electron. تتكامل هذه الأجزاء لتغطية بيانات الأطراف، المخزون والأثواب، المشتريات والمبيعات، الخزينة والحسابات، الموارد البشرية، التصنيع، التقارير والطباعة.

يتضح ذلك من مسارات الواجهة في [src/App.tsx](../src/App.tsx)، وتسجيل وحدات API في [server/src/app.ts](../server/src/app.ts)، وسكربتات البناء والاختبار في [package.json](../package.json). كما يحتوي المستودع على وثائق تشغيل وتقارير تاريخية عديدة؛ وهي مرجع مفيد، لكنها لا تثبت بمفردها أن كل خطوة تشغيلية أو نشر قد نُفذت أو أن كل ميزة اجتازت اختباراً حديثاً.

## 2. الخريطة التقنية للمشروع

| القسم | الموقع | المسؤولية |
|---|---|---|
| واجهة المستخدم | `src/` | الشاشات، التنقل، النماذج، الترجمة، إدارة حالة العميل، واستدعاء API. |
| الخادم | `server/src/` | نقاط API، التحقق من الهوية والصلاحيات، منطق الأعمال، والتعامل مع PostgreSQL. |
| تطبيق Windows | `electron/` | تشغيل الواجهة كتطبيق مكتبي، جسر IPC محدود، الطباعة واختيار الملفات، وتهيئة الخادم المضمّن والاتصال بقاعدة البيانات. |
| قاعدة البيانات | `server/src/db/` و`server/src/db/migrations/` | اتصال PostgreSQL، نطاق الشركة، التهيئة الأولية والترحيلات المتعاقبة. يوجد في المجلد حالياً 118 ملف ترحيل؛ وهذا عدد الملفات الموجودة، لا دلالة على ما طُبّق فعلياً على أي قاعدة. |
| أدوات التطوير والتشغيل | `scripts/` و`server/src/scripts/` | البناء والتغليف، الفحص، الاستيراد والإصلاح، التشخيص، وبعض مهام النشر والتشغيل. |
| الاختبارات | بجوار الوحدات وضمن سكربتات npm | اختبارات وحدات وتكامل لمسارات محددة في المخزون والفوترة والاستيراد والطباعة والموارد البشرية والتصنيع وغيرها. |
| الوثائق | `docs/` وملفات الجذر | أدلة تشغيل وتقارير تغييرات وتحليلات ومواصفات سابقة. لم يظهر ملف README عام في جذر المشروع ضمن الملفات المفحوصة. |

### التقنيات الظاهرة في الإعدادات

- الواجهة: React 19 وTypeScript وVite وTailwind CSS، مع React Router.
- حالة الواجهة: Zustand؛ وتوجد خدمات API منفصلة ضمن `src/lib/api/`.
- الترجمة: i18next، مع مجلدين للواجهات العربية والتركية (`src/locales/ar` و`src/locales/tr`).
- الخادم: Fastify 5 وTypeScript؛ ويتصل بـ PostgreSQL عبر `pg`.
- التحقق من بيانات البيئة: Zod في `server/src/config/env.ts`.
- تطبيق سطح المكتب: Electron؛ وتتضمن حزم المشروع أدوات Excel وQR/الباركود والطباعة وإنشاء المستندات، بحسب الاعتمادات والملفات المستخدمة.

## 3. واجهة المستخدم ووحدات العمل

تُعرّف [src/App.tsx](../src/App.tsx) صفحات النظام ومساراتها. يستخدم التطبيق `BrowserRouter` في المتصفح و`HashRouter` داخل Electron، وتوجد معالجة مساعدة للتنقل الخلفي. وتضم `src/components/` و`src/lib/` مكونات ومساعدات مشتركة للوحدات التالية.

### أ. الدخول، لوحة التحكم، إعداد النظام والشركات

- تسجيل الدخول والخروج، واسترجاع معلومات الجلسة.
- تهيئة النظام، إعدادات سطح المكتب، وتفضيلات العرض والطباعة.
- صفحات الشركات/الشركاء والتفعيل وإدارة حالة الترخيص.
- إظهار وحدات النظام بحسب المستخدم وإمكاناته؛ توجد أدوات مشتركة للصلاحيات في `src/hooks/usePermissions.ts`.

### ب. العملاء والموردون

- إدارة سجلات العملاء والموردين.
- عرض كشوف الحساب وسجل النشاط لكل طرف.
- استيراد بيانات العملاء القديمة، وإدارة خصومات العملاء حيث تكون مفعّلة.
- دعم بيانات الأطراف باعتبارها مدخلات مشتركة للمبيعات والمشتريات والدفعات والتقارير.

المسارات المقابلة ظاهرة في `customers` و`suppliers`، وتوجد خدمات API وسجلات نشاط وكشوف طرف في الواجهة والخادم.

### ج. المخزون والمستودعات والأقمشة

- إدارة بيانات الأقمشة الأساسية: الأصناف والتصنيفات والألوان والمتغيرات والتصنيف.
- إنشاء الأثواب/الرولات وتعديلها وعرض تفاصيلها وحركتها.
- إدارة المستودعات ومناطق التخزين، والاستلام والتسليم، والتحويلات والهدر.
- استيراد المخزون ودفعات الاستيراد، وسجل حركات المخزون.
- إدارة الخيوط ولوطات الخيط عبر واجهة مخزون الخيط وواجهات `yarn-lots`.
- القص والتسعير بالجملة والاستهلاك/الإهلاك، وفق الشاشات والمسارات الموجودة.
- إعداد وطباعة الملصقات وبطاقات الألوان (Cartela)، ومتابعة التسليم والعهدة والمخزون المرتبط بها.

من أمثلة الشاشات: `src/pages/Inventory.tsx`، ومجلد `src/pages/inventory/` و`src/pages/cartela/`. وتظهر مقابلات API في مسارات الأثواب والتحويل والهدر والاستيراد والملصقات والكارتيلة ضمن `server/src/app.ts`.

### د. المشتريات والاستيراد والأعمال الخارجية

- استيراد ملفات Excel للمشتريات ومراجعة دفعات الاستيراد.
- تسجيل فواتير المشتريات وإدارة مرتجعات الفواتير وكشوفها.
- متابعة الأعمال/التشغيلات الخارجية، استلامها، مطابقة بنودها، وعمليات الإدخال والتسليم.
- ربط هذا المسار بحركة المخزون وبالموردين والفواتير بحسب واجهات API المخصصة.

الصفحات الأساسية موجودة في `src/pages/Purchases.tsx` و`src/pages/purchases/`، مع خدمات مثل `purchaseImportApi` و`externalJobsApi` و`intakeOperationsApi`.

### هـ. المبيعات والطلبات والفوترة

- إنشاء وتعديل فواتير المبيعات والمشتريات.
- تسجيل فواتير الإرجاع والتبادل، وعرض كشف/تفاصيل الفواتير.
- إدارة طلبات العملاء ودورة حالتها، مع واجهات مستقلة لسير العمل والتنبيهات.
- ربط عمليات البيع بالمخزون والعملاء والتحصيلات بحسب واجهات الخادم ذات الصلة.

تظهر هذه الوظائف في صفحات `Sales.tsx` و`Purchases.tsx` و`ReturnInvoices.tsx` و`InvoiceForm.tsx` و`CustomerOrdersPage.tsx`، وفي واجهات API للفواتير والطلبات.

### و. الخزينة والحسابات والمصروفات

- إدارة الصناديق/الخزائن والتحويل بينها، وسجل الحركة وإعدادات الخزينة.
- متابعة الشيكات، سندات القبض والصرف، وسجلات السندات.
- إدارة أسعار الصرف والعملات، والمصروفات التشغيلية.
- صفحات الحسابات والقيود المالية والتقارير المالية/تفاصيل الربحية.

تتوزع الواجهات على `src/pages/treasury/` وصفحات `Accounting.tsx` و`Journal.tsx` و`Expenses.tsx` وصفحات السندات. ويضم الخادم وحدات `cashbox` و`checks` و`vouchers` و`exchange-rates` و`finance` و`financial-audit` و`operating-expense`.

### ز. الموارد البشرية والرواتب

- إدارة الموظفين والحضور والمراجعة الشهرية والسنوية.
- معالجة الرواتب وسجلاتها والاستيراد المرتبط بها.
- منطق مساعد لحساب الغياب والعمل الإضافي والأرصدة والإجازات وتركيب الأجر وبنود الراتب.

واجهات المستخدم موجودة في `src/pages/hr/` و`Salaries.tsx`، بينما تتضمن خدمات الخادم `attendanceService` و`payroll` ومجلد `server/src/services/hr/`.

### ح. التصنيع

- إدارة أوامر العمل ومراجع وبيانات مواصفات المنتج.
- متابعة مراحل التدوير/التسدية، والتصميغ، والنسج، وإتمام الجودة.
- التعامل مع مواد الخيط ووصفات ومراجع التصنيع وإصدارات المواصفات.
- تسجيل التنفيذ والتكاليف والتقارير التشغيلية والطباعة ذات الصلة.
- ربط بعض المسارات بالمصنعية الخارجية ومتابعة استلامها ومطابقتها.

للتصنيع شاشة رئيسية في `src/pages/Manufacturing.tsx` ومكونات متخصصة تحت `src/components/manufacturing/`. ويؤكد تسجيل الخادم وجود مجموعات مستقلة لأوامر العمل والتسدية والتصميغ/المقاسات والنسج والجودة والتكلفة والطباعة والمراجع في `server/src/app.ts`. وجود هذه المسارات يثبت وجود الشيفرة، لا اكتمال كل سير إنتاج ميداني أو اعتماده.

### ط. التقارير والطباعة والتكاملات

- مركز تقارير وصفحات تقارير تشغيلية ومالية، مع واجهات تقارير مخصصة.
- إنشاء/طباعة الملصقات والفواتير والكشوف ومستندات PDF.
- تكامل Electron مع طابعات Windows واختيار ملفات Excel ومجلدات حفظ PDF.
- توجد وحدات للذكاء الاصطناعي وTelegram في الواجهة والخادم؛ تفعيلها الفعلي يعتمد على الإعدادات ومفاتيح البيئة المتوفرة.

## 4. الخادم وطبقات المنطق

### نقطة التشغيل والتوجيه

- `server/src/index.ts` يقرأ الإعدادات، يبني تطبيق Fastify ثم يستمع على المنفذ المحدد.
- `server/src/app.ts` يسجل مجموعات المسارات تحت بادئة `/api`، بما فيها الصحة والنظام والتفعيل والمصادقة، والبيانات الأساسية، والمخزون، والفواتير والخزينة والموارد البشرية والتقارير والتصنيع.
- `server/src/middleware/` يحتوي على التحقق من المصادقة ومعالجة الأخطاء.
- `server/src/services/` يحتوي على منطق الأعمال، مع مجلدين متخصصين للخدمات المتعلقة بالذكاء الاصطناعي والموارد البشرية.
- `server/src/utils/` للمساعدات المشتركة، و`server/src/scripts/` لأدوات صيانة/تشخيص منفصلة عن طلبات API الاعتيادية.

### الهوية والصلاحيات والنطاق

- رمز جلسة JWT يتضمن هوية المستخدم والشركة والدور والصلاحيات.
- طبقة المصادقة تتحقق من حالة المستخدم والجلسة، وتوجد معالجة منفصلة لمدير المنصة.
- تتضمن قاعدة البيانات مساعد `companyScope.ts`، ما يدعم عزل/تحديد نطاق بيانات الشركة.
- يوجد مسار تفعيل للنظام، ويمكن أن يمنع وصول API إلى وظائف الأعمال ما لم يكن التفعيل فعالاً؛ مع استثناء مسارات الصحة والدخول والتفعيل المحددة في التطبيق.

هذه النقاط تصف الشيفرة الموجودة، ولا تحل محل تدقيق أمني أو اختبار عزل كامل.

### البيانات والترحيلات

- الاتصال بقاعدة البيانات مركزي عبر `server/src/db/pool.ts`.
- ترحيلات SQL تحفظ تحت `server/src/db/migrations/` ويُتابع تطبيقها بجدول `schema_migrations` بواسطة `server/src/db/migrate.ts`.
- توجد أدوات seed وإعادة تهيئة، وأدوات استيراد/إصلاح بيانات ضمن المشروع.
- عدد ملفات الترحيل لا يحدد حالة قاعدة بيانات بعينها؛ يتطلب ذلك فحص قاعدة البيانات المقصودة وسجل الترحيلات فيها.

## 5. تطبيق Electron وطرق التشغيل

يتولى [electron/main.ts](../electron/main.ts) العملية الرئيسية، بينما يعرّف [electron/preload.ts](../electron/preload.ts) قائمة IPC محدودة باسم `fabricApp` بدلاً من منح الواجهة وصول Node.js مباشراً. إعدادات Electron تضبط عزل السياق وتعطيل Node integration في واجهة العرض.

في النسخة المكتبية المجمعة، يوجد مسار لتشغيل Fastify المضمّن محلياً على `127.0.0.1:4010`، مع إمكان توصيل PostgreSQL عبر نفق SSH محلي أو اتصال PostgreSQL عام اختياري وفق ملف الإعداد. كما يدعم Electron إعداد الطابعات، والطباعة المباشرة/الصامتة، وإنشاء PDF، واختيار ملفات Excel. ويحتوي المشروع أيضاً على وضع واجهة ويب عبر Vite، وعلى أوامر تشغيل تطوير تفصل الواجهة والخادم أو تشغلهما مع Electron.

أوامر البناء والفحص معرفة في `package.json`؛ ومن أمثلتها `npm run dev:renderer` و`npm run dev:server` و`npm run electron:dev` و`npm run build` و`npm run electron:build`. لا ينبغي اعتبار وجود السكربت دليلاً على نجاح تشغيله في كل بيئة.

## 6. الاختبارات والصيانة والتوثيق

- `npm test` يشغّل مجموعة كبيرة من اختبارات الوحدات المحددة صراحة في `package.json`، وتشمل مجالات متعددة من الواجهة والخادم.
- توجد مجموعات إضافية منفصلة لتكامل التصنيع مع قاعدة البيانات، وعزل الشركات، والتحويلات المخزنية، واختبارات TypeScript للخادم والواجهة.
- `predeploy:check` يجمع فحوص الخادم والواجهة والاختبارات المحددة في المشروع.
- `scripts/` يضم أدوات بناء وتشغيل وتحقق واستيراد وإصلاح وتشخيص؛ ويجب مراجعة وصف كل سكربت قبل تشغيله، خصوصاً ما يتصل بقاعدة البيانات أو الخوادم.
- `docs/` يحتوي على أدلة وتقارير وملاحظات تنفيذ ومراجعات سابقة. بعضها مؤرخ أو مرتبط بمرحلة بعينها، لذلك ينبغي الرجوع إلى الشيفرة الحالية وسجل قاعدة البيانات قبل اتخاذ قرار تشغيلي.

## 7. ملاحظات وحدود التقرير

1. هذا جرد بنيوي ووظيفي مبني على أسماء الملفات والمسارات والإعدادات والشيفرة المقروءة؛ وليس تدقيقاً لكل دالة أو اختباراً لقبول الأعمال.
2. لم يُشغّل بناء أو اختبار ضمن إعداد هذا التقرير، لأن العمل توثيقي فقط. لذلك لا يتضمن حكماً على نجاح الحالة الحالية وقت التشغيل.
3. لم تُفحص ملفات الأسرار أو إعدادات البيئة المحلية، ولا محتويات ملفات العمل التجارية أو ملفات Excel/PDF. وهي ليست جزءاً من وصف أقسام الشيفرة.
4. لا يثبت التقرير أن كل شاشة مستخدمة في الإنتاج، أو أن جميع المزايا مكتملة أو منشورة، أو أن الترحيلات طُبّقت على قاعدة إنتاج.
5. للحصول على شهادة تشغيل/نشر، يلزم فحص البيئة المقصودة، وسجل الترحيلات، ونتائج الاختبارات، وإعدادات النشر الفعلية بصورة منفصلة.

## 8. خلاصة

يتكون CLOTEX من واجهة ERP متعددة الوحدات، وخادم API ومنطق أعمال متصلين بقاعدة PostgreSQL، مع دعم تطبيق Windows مكتبي وعمليات استيراد وطباعة وتقارير. أبرز المجالات الوظيفية في الشيفرة هي المخزون والأقمشة، العملاء والموردون، المشتريات والمبيعات والطلبات، الخزينة والحسابات، الموارد البشرية، التصنيع، والتقارير والإعدادات. ويُعد `server/src/app.ts` و`src/App.tsx` أفضل نقطتي دخول لمتابعة خريطة API وصفحات النظام على التوالي.
