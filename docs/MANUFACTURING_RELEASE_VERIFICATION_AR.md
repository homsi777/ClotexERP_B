# تحقق إصدار التصنيع

> تقرير تاريخي للدورة الأولى. استُكملت البنود الثلاثة التي كانت خارج نطاقه؛ راجع `MANUFACTURING_COMPLETION_REPORT_AR.md` للنتيجة الحالية.

## النطاق المثبت عملياً

اختبار HTTP حقيقي عبر Fastify وPostgreSQL 17 محلي، دون الاتصال بالإنتاج:

- مواصفة معتمدة كبيانات اختبار، إنشاء أمر إنتاج وإصداره وتثبيت Snapshot.
- إنشاء أمر تسدية وإصداره وكارت السداء، طلب الخيط وصرفه وتسوية المرتجع والهالك.
- إكمال التسدية وإنتاج المطواة، ثم مساران: النسج مباشرة، أو التصميغ ثم النسج.
- تسجيل إنتاج الوردية وإغلاق التشغيل، فحص دفعة الإنتاج واعتمادها.
- استلام جزئي للرولات في المخزون مع الباركود وحركة INTERNAL_PRODUCTION والتتبع إلى الدفعة والتشغيل.
- إغلاق أمر الإنتاج مع سبب موثق عندما تقل الكمية المقبولة عن المستهدفة.

نتيجة السيناريوهين: صرف 40 كغ، مرتجع 4 كغ، هالك 2 كغ، استهلاك 34 كغ، ورصيد خيط 64 كغ من أصل 100. استلام أربعة رولات بمجموع 180 متراً، لكل رول حركة مخزنية واحدة.

## حالات الرفض المختبرة

- مستخدم بلا صلاحية، ومحاولة استخدام شركة مخالفة لشركة المستخدم.
- تكرار صرف الطلب نفسه، وتكرار إسناد المطواة إلى تشغيل أو أمر تصميغ مفتوح.
- طلبا وردية متزامنان بالقراءات نفسها: ينتج طلب واحد فقط دفعة إنتاج، ويرفض الآخر.
- إنتاج صفري، واستلام قبل اعتماد الجودة، وتجاوز الكمية النظيفة المعتمدة.
- تكرار استلام رول أثناء الاستلام الجزئي، وإغلاق أمر إنتاج قبل إنهاء الجودة والاستلام.
- إغلاق مع نقص في الناتج المقبول دون تسجيل السبب.

## الإصلاحات

- استكمال المفتاح المركب لأسباب التوقف في 083 الذي كان يمنع تثبيت الترحيل.
- تحويل موضع substring إلى int صراحة في تسلسل أوامر التسدية والكروت، لمنع تكرار الرقم الثاني.
- ترحيل 093 لإضافة updated_at إلى المطاوي المصمغة؛ كان مسار بدء النسج يفشل بدونه.
- منع إسناد المطواة مرتين والتحقق من حالتها عند بدء التصميغ أو النسج.
- مطابقة بداية عداد الوردية مع القراءة السابقة تحت قفل التشغيل لمنع تكرار الإنتاج.
- حماية استلام الرولات المتكرر، وتسلسل استلام دفعات التصنيع ضمن الشركة عند توليد الباركود.
- إضافة إغلاق أمر الإنتاج إلى API والواجهة، مع فحص العهد والمراحل والجودة والمخزون وتسجيل الحدث والسبب.

## أوامر التحقق

اختبارات المنطق والطباعة: `npm.cmd run test:manufacturing-reference`.

اختبارات PostgreSQL اختيارية، لا تقرأ .env ولا تستخدم اتصال الإنتاج. يلزم مثيل محلي مخصص على 127.0.0.1:55483 وقاعدة clotex_manufacturing_test:

```powershell
$env:CLOTEX_MANUFACTURING_LOCAL_TESTS='1'
$env:CLOTEX_MANUFACTURING_TEST_DATABASE_URL='postgresql://clotex_test@127.0.0.1:55483/clotex_manufacturing_test'
npm.cmd run test:manufacturing-db
```

نجح تثبيت الترحيلات الـ92 في مخطط جديد، واختبار مرجع أسباب التوقف بين الشركات، والحفاظ على CUT وINTERNAL_PRODUCTION.

نجح `server:check` و`build`. فشل `lint` الشامل بأخطاء TypeScript خارج التصنيع؛ شُغل أيضاً على فرع clotex قبل الدمج وأظهر الأخطاء نفسها. لا يوجد ادعاء بنجاحه.

## حدود الاعتماد

هذه شهادة تحقق للدورة التشغيلية المذكورة، وليست إثباتاً لاكتمال جميع بنود الخطة الرئيسية. لم تُجرَ تجربة واجهة مرئية أو اختبار تحميل أو اختبار نشر على الخادم. استيراد Excel والطباعة لديهما اختبارات منطق مستقلة؛ الاختبار المتكامل يبدأ بمواصفة معتمدة مجهزة للاختبار.

التكلفة الصناعية الشاملة والقيود المالية الآلية، استهلاك اللحمة ومواد التصميغ من المخزون، الربط الكامل بالتصنيع الخارجي، والتخصيص الآلي للتسليم والفوترة ليست ضمن الدورة المثبتة هنا، ولا يجوز وصفها بالمكتملة اعتماداً على هذا التقرير. مسارات الجودة ذات إعادة التشغيل أو الانتظار تمنع إغلاق أمر الإنتاج لحين تسويتها؛ لم نثبت دورة معالجة مستقلة لإعادة التشغيل.

قبل النشر يجب تطبيق الترحيلات الجديدة بالآلية المعتادة مع النسخة الاحتياطية. لم يُعدّل خادم الإنتاج. إذا كانت نسخة سابقة من 083 قد طُبقت خارج الفرع الرئيسي، يجب مقارنة مخططها قبل النشر لأن 083 تطور في فرع التصنيع؛ إعادة تشغيل migrator لا يعيد تنفيذ ترحيل مسجل سابقاً.
